{% load ui %}{% comment %} The one list toolbar (docs/ui-standards.md section 5, rule 1), inside the list's section.card.vr-table-card above the table: search, up to three everyday filters, More filters (a Bootstrap collapse), Apply, Clear all when anything is active, Columns at the right, then the active filters as removable chips. A GET form: the server filters, sorts and paginates; changing a filter returns to page 1. Built from includes/grid_search.html, grid_columns_button.html and filter_chips.html. On a phone (below 576px) the toolbar collapses behind one "Filter and sort" button with the count of active filters and a one-line summary of them (docs/ui-standards.md section 13): the form, with "Clear all" and "Columns", opens in a bottom sheet ({% sheet below="sm" %}, includes/sheet.html) with a "Sort by" section, and the chips row gives way to the summary. static/js/app.js fills the sheet's [data-vr-sort-slot] with copies of the table's sort links and appends "Sorted by " to the summary; without script the table's own "Sort by" chips stay. From 576px up the sheet is plain inline content and the toolbar looks and works as it always did. Parameters: label accessible name of the form, e.g. "Filter client organizations" (required) q current search text; placeholder, search_id (default "grid-q") tune the search box no_search truthy for a list without free-text search inline up to three bound fields shown in the row (e.g. a list built in the view) more bound fields behind More filters; omit when there are none more_open truthy when one of the "more" filters is active; the panel also opens when invalid invalid the filter form's errors (filter_form.errors); opens More filters chips the active filters as [{label, value, remove_url}] (active_filters); shown as removable chips under the toolbar active truthy when any filter or search is active (a default value is not); shows Clear all. chips or q also count clear_url target of Clear all; default request.path grid the table's data-vr-grid key: renders the Columns button; omit for entry grids sort the current sort value, carried when hidden is not given hidden bound hidden fields to carry; without it sort and rows per page (request.GET.per_page) are carried The button's count and the summary of the active filters are derived from chips (or active_filters) and q. Documented page reads ({% grid_toolbar %}, core/templatetags/ui.py): q, placeholder, inline, more, more_open, active and sort when not passed, and filter_form and active_filters (for invalid and chips when those are not passed); the list views put them in the context. The form posts to request.path.
