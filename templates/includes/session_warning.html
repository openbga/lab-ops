{% load static ui %}{% comment %} The warning before automatic sign-out (accounts/sessions.py), on every page of a signed-in session: layouts/document.html includes it when account_session is set (staff pages and the client portal). The hidden element carries what static/js/session.js needs: the status and Stay signed in addresses, the sign-in page, the seconds left as the server measured them for this request, and how long before each ending the page warns. The script asks the status address (not activity) before it warns, then shows one alert dialog: - before the sign-out for no activity: "Still there?", with Stay signed in (primary, focused; activity, so it extends the session) and Sign out (allauth's logout, a POST); - before the longest session ends: "Your session ends soon", with Close (nothing extends it). When both are due the one that ends first is shown. The countdown (m:ss) is part of the dialog's description, read once when the dialog opens; its updates each second are not announced. Elements marked data-vr-session-for belong to one of the two; the script shows that one's. Parts are found by their data attributes, not ids: form-dialog.js renames the ids of the page behind an open form. The line marked data-vr-session-kept shows while a form on the page that keeps typing (static/js/kept-typing.js) holds something typed: once the session has ended, the script sends it to the keep address (accounts/kept.py) before going to the sign-in page. Without JavaScript there is no warning; the server signs the session out all the same. {% endcomment %}{% url 'account-session' as status_url %}{% url 'account-session-continue' as continue_url %}{% url 'account-session-keep' as keep_url %}{% url 'account_login' as sign_in_url %}{% url 'account_logout' as logout_url %} {% with times=account_session.as_json %}
